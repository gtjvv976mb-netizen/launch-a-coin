# Live launch boundary review — 28 October 2026

Read-only review covered live auth, trusted composition, preparation, confirmation, recovery, signed relay, Wallet Standard control and the separate browser wire verifier. Source fixes were made by their owners. The adapter was refrozen after an approved serialization-overflow error fix. No real relay, wallet prompt or deployment was executed by this review.

Two material concurrency defects were found and corrected before freeze:

1. **NFT-key replacement could miss a concurrently prepared/submitted old transaction.** Replacement now atomically compares its complete checked plan-ID set, stage, NFT identity, binding, signatures and receipts after the RPC expiry/absence check. Plan insertion guards the current snapshot; relay guards the current Core address. This closes the identified window in which old and replacement asset transactions might both land.
2. **A stale pending confirmation could overwrite a newer verified signature/receipt.** Confirmation now CAS-guards the intent and plan signature, preserves verified receipts, and does not bind arbitrary unsubmitted pending signatures. Abandonment also compares the full prepared-plan set and snapshot after RPC checks.

Independent reinspection confirmed those guards at plan insertion, replacement, abandonment, relay and both confirmation stages. The backend owner added deterministic concurrency-hook regressions. No additional blocking race was found.

A separate retry defect was also corrected: an expired, unlanded NFT transaction previously retained its pending-stage signature when a same-key fresh transaction was prepared. The server now requires finalized account absence and expiry of every historical NFT plan before atomically clearing that stage signature, even when the NFT address stays the same. Signed transaction history remains immutable. The UI exposes card review while card confirmation is uncertain, so the safe server recovery path remains accessible. Independent reinspection confirmed these changes; the backend regression covers refusal before expiry and successful same-key retry afterward.

The initial browser check incorrectly required a wrapped-SOL quote key for native SOL create-only instructions; the owner corrected it. Browser validation now checks exact Pump operations/arguments/accounts, selected-quote buy amount/minimum, Core owner/metadata/binding attributes and authority removal, compute limit/price/priority-fee math, message hash, signer set and blockhash. It rejects lookup tables, extra operations, changed wallet messages and missing/changed partial signatures. Actual SDK plans pass that independent verifier for every reviewed quote and Core issuance.

Other controls reviewed coherently: domain-bound expiring single-use challenges and atomic nonce consumption; secure strict-origin HTTP-only sessions; wallet-owned intent lookups; trusted canonical composition attestations; public content hashes; immutable design/quote/metadata bindings; exact signed bytes persisted before relay; fresh mainnet quote/fee/balance/simulation checks; finalized Pump verification before NFT creation; immutable Core binding data; account-only NFT recovery; and finalized expiry/absence before replacing keys.

Nonblocking observations were sent to owners: explicit server logout makes wallet disconnect semantics clearer; cached token receipts can retain the old auxiliary NFT-address label after a safe unissued-key rotation, although the current intent and fresh NFT-stage verification use the replacement address. Neither observation permits fund movement or duplicate issuance.

Validation: **23 integration tests / 415 assertions**, TypeScript, all-16-quote/Core browser compatibility and separate unsigned mainnet program simulations passed. This does not claim a completed wallet-signed production launch: actual user approvals, broadcast and funded end-to-end confirmation were not exercised.
