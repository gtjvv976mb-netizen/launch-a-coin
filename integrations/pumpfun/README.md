# Launch a Card — pump.fun and creator NFT integration

`src/live.ts` prepares real Solana mainnet transactions for a pump.fun token and its separate creator-owned Metaplex Core NFT. Wallet Standard supplies the creator signature; the browser also creates and signs the new token/asset identities without uploading their private keys. This package never generates a creator signature or holds wallet keys. App activation requires production persistence, public artwork/metadata, mainnet RPC and an explicit live-enable setting.

Pinned dependencies: official Pump SDK **4.1.0**, PumpSwap **2.1.0**, Core **1.10.0**, Umi **1.6.0**, web3.js **1.99.0**. The lockfile pins the resolved tree. Install scripts are disabled; native bigint uses its JavaScript fallback.

## Server interface

All functions accept an injected connection from `createMainnetConnection(rpcUrl)`, keeping RPC credentials on the server.

- `prepareTokenTransaction(input, {connection})` revalidates mainnet, the exact reviewed quote, decimals/program, admission and new mint. Optional atomic initial buys use fresh reserves/fees, exact quote base units and integer basis-point minimums. Custom buys require sufficient unfrozen quote balance. Complete unsigned transactions are simulated before wallet review.
- `measureTokenTransaction({creator, name, symbol, tokenMetadataUri, quoteKey}, {connection})` returns the exact wire size of that coin transaction with and without an initial buy (the amount never changes it), from the same builders, the real Pump accounts, existing ATAs and the same lookup-table choice. `limit` is the wallet size target (1,072 bytes: Solana's 1,232-byte limit less 160 bytes for wallet assertions). `buyBlocked: "issuer-controls"` marks a tokenized-stock quote, whose first buy prepare refuses because wallets warn on permanent-delegate tokens (`ALLOW_PERMANENT_DELEGATE_QUOTE_BUY` in `src/index.ts`). Use it before uploading anything.
- `validateSignedWalletTransaction(plan, transactionBase64)` checks the returned message against the plan under the shared wallet rule (`src/wallet-guards.ts`, also run in the browser before the page co-signs): the same decompiled message, or that message with read-only Lighthouse v2 assertions appended (program `L2TExMFKdjpN9kozasaurPirfHy9P8sbXoAN1qA3S95` only; one plan account each; no new key but the program; every plan key's flags, the signers, the lookups and every plan instruction including both compute-budget instructions unchanged), and a wallet-refreshed blockhash. Then payer, signer set and all Ed25519 signatures over the returned message. It returns the deterministic signature, the unchanged bytes and `signedMessageSha256`, which every later finalization check must expect.
- `checkSignedWalletTransaction({plan, transactionBase64}, {connection})` runs the read-only pre-send checks in order: signatures against the plan, signature status, blockhash expiry (a refreshed blockhash must still be valid on the RPC), then a sigVerify simulation. It returns `lastValidBlockHeight`, after which those signed bytes can no longer land (for a refreshed blockhash, the newest last valid height plus `REFRESHED_BLOCKHASH_MARGIN`): persist it with the bytes and make every abandon or replace gate wait past it. A signature the chain already has returns `landed` (save and recover it). An expired blockhash or failed simulation throws `SignedTransactionNotSent`: nothing was sent, so the caller keeps the stage re-preparable.
- `broadcastSignedWalletTransaction({plan, transactionBase64}, {connection})` is the authenticated server relay. **Run the checks first, then atomically persist the signature and exact signed bytes, then broadcast.** Transport uncertainty returns the same signature; retries never rebuild or re-sign it. `sendSignedWalletTransaction` runs both for callers without state.
- `verifyTokenLaunch(input, {connection, signature, expectedMessageSha256})` independently verifies finality, successful execution, exact Pump creation/optional buy, mint/curve owners, creator, quote and token metadata. Trailing Lighthouse assertions are accepted only when `expectedMessageSha256` (the stored signed hash) matched; `verifyCreatorNft` does the same.
- `prepareCreatorNftTransaction(input, {connection, tokenSignature, tokenMessageSha256})` requires fresh finalized token verification, then prepares one Core asset owned by the creator. Creation and permanent metadata authority removal are atomic. Its sole plugin is immutable binding Attributes; there is no Royalties plugin or collection. A matching existing asset returns `already-created` instead.
- `verifyCreatorNft` and `recoverCreatorLaunch` verify the existing Core account even without a known NFT signature. Recovery distinguishes token pending, token created/NFT pending and complete.
- `assertNftMintReplaceable` / `assertTokenMintReplaceable` require finalized expiry and an absent old mint. The expiry height and slot come from one finalized epoch bank; the subsequent absence read must meet that minimum context slot. The server must also atomically compare the checked intent and complete prepared-plan set after RPC verification.

`LiveLaunchInput` extends the base creator/mint/name/symbol/metadata/quote/card input with `nftMint`, optional `nftName`, initial-buy atoms, slippage, and required live commitments `renderedCardSha256` / `nftMetadataSha256`. Reviewed source-art hashes are checked against all 96 approved WebPs.

Plans contain an unsigned v0 wire transaction, exactly two signer public keys, message hash, blockhash/expiry, stable launch binding, decoded summary and wallet costs. Costs show network/priority/rent-program components, total simulated SOL debit, optional quote spend and minimum six-decimal token output. A small reserve buffer is shown separately. The binding excludes the ephemeral Core address so a safely expired, unissued key can be replaced without changing approved metadata.

Every prepared transaction stays at or under 1,072 bytes, leaving 160 bytes for wallet assertions (Phantom also names a transaction close to the size limit as a warning trigger). A coin transaction over that without a table (every create + first buy: 1,203-1,276 bytes) is compiled against pump.fun's own create lookup table `Hyif6eWb8x88RVrvjPfabsgRYnwkVnyByEXTVTXbUcyP`, as pump.fun's own creates are, using only 14 pinned entries; the table is re-read before each use (lookup-table program owner, never deactivated, every pinned entry) and otherwise left out. With it, SOL and token-quote create + buy measure about 865-975 bytes. The coin's priority fee is sampled on the two write locks every create_v2 shares (Mayhem program and SOL vault), at the 75th percentile, 1,000-200,000 micro-lamports per unit; the card's on the creator. The compute limit is 1.2 x simulated use + 50,000 units, enough for nine wallet assertions. Freshly verified existing ATA setup is omitted when safe, and metadata URLs are kept short. Oversized transactions fail explicitly; callers can choose an initial buy of zero. The adapter never silently removes a buy. Stock quotes do not give the creator token or NFT company-equity rights.

## Verification

```sh
bun install --frozen-lockfile --ignore-scripts
bun test tests
bun run typecheck
```

**24 tests / 421 assertions and TypeScript pass.** Checks cover all 16 quote identities, all 48 designs, all 96 source hashes, positional accounts, live buy inputs/minimums, simulation and packet failures, immutable Core state, signatures, retry uncertainty, context-bound expiry/absence and separate-stage recovery. Synthetic signing/relay tests use a fake blockhash and mock-only RPC. Actual SDK plans pass the app’s independent browser verifier for all 16 quotes and Core issuance.

Separate **unsigned mainnet program simulations** passed at slots 462361248 (TSLAX token create, 1011 bytes) and 462361249 (Core create/authority removal, 885 bytes). Deserialized Core state confirmed creator ownership, both immutable authorities, six binding attributes and no Royalties plugin. These were independent simulations: no token/NFT was issued, no wallet prompt was used and nothing was sent. Evidence is retained under `output/research/pump-custom-pairs-2026-10-28/`; `scripts/readonly-simulation.ts` performs only public reads and unsigned simulations.
