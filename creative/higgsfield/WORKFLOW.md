# Required card-artwork workflow

Owner instruction, 29 October 2026: **use Higgsfield for all card designs to maintain premium, consistent cards.** This requirement applies to standard, premium, limited-edition, stock and meme artwork, both faces, and custom card-based brand logos. Later explicit owner directions take precedence.

## Generate through Higgsfield

Use the connected Higgsfield generation tools for new decorative artwork and creative redesigns. Read the current model schema and obtain the current quote before submitting within the owner's approved allocation. A provider preference is not an additional credit budget. Retain returned job IDs and wait for completed results; recover uncertain submissions before retrying. Do not silently use built-in image_gen, another provider, or CSS/SVG illustrations as replacement card artwork.

Use an approved front/back pair as the visual reference for construction, material separation and lighting. Write one shared brief containing the design identity, palette, metal/enamel/paper materials, ornament density, foil treatment, edge construction and intended content apertures. Apply that same brief to both faces. Preserve distinct themes while matching the collection's physical construction and quality.

## Preserve the shared template

The canonical card is 63:88 with smooth rounded corners. New catalogue fronts must follow the current Launch a Card v2 content grid: aligned 10%–90% width; creator-art window at15%–59% height; details extending to92.5%; safe ink insets around ornaments. Use the current renderer metrics as authority if implementation changes.

Keep the creator's art aperture and live-information surfaces clear. Theme imagery belongs in the surrounding card design and reverse; it must not obscure or duplicate the creator's token image. Both former footer slots, platform/owner footer labels, coin serials and decorative tier/theme names stay removed. Carry matching native material through the bottom edge.

Catalogue decoration remains text-free. An explicit owner request for lettering in a particular brand asset is a scoped exception: the pending custom logo must say exact lowercase **launchacoin** once. This does not rename the platform or add lettering to unrelated templates.

Each reverse should be recognizable and coherent with its front's palette, border construction and material family. Keep fittings inside the silhouette. Avoid clipped ornaments, sharp protrusions, excessive bloom and unresolved placeholder marks. Compare both faces together before integration.

## Compose and export consistently

Code composes creator content, the shared print layout, responsive views, immutable NFT images and interaction. Retain the shared canonical compositor/atlas workflow so browser and NFT export use the same surfaces. Resizing, format conversion, cropping/export correction and content placement preserve the approved artwork; they do not count as new Higgsfield generations.

Keep creator art centered, filling the full aperture, with no implicit saturation/sepia filter. Browser and export must use matching content typography and measurements. A trusted-output change advances the renderer version for new compositions without rewriting saved intents or immutable image URIs. Check current catalogue content geometry, pinned atlas/preview hashes and rounded alpha masks after integration; a new theme must not introduce a private layout fork.

Existing verified Higgsfield finishes may be reused for supported pair presets without inventing extra design identities or claiming new mascot artwork. If the owner requests a genuinely new theme, generate its new art through Higgsfield.

## Review the result

Inspect actual returned media. Check front/back material match, creator-art clearance, fixed content positions, continuous lower material, rounded corners and phone-scale clarity. For a newly integrated card, inspect desktop and phone renders, both faces through a full turn, shimmer, clipping and touch rotation. Report physical-device checks that were not performed. For a social logo, inspect exact requested lettering and square/circular crops. Run checks appropriate to changed code; image-only proposals do not need an unrelated application test suite.

## Keep provenance

Record provider/model, exact prompts and references, approved allocation, quoted cost, completed job IDs and source URLs. Preserve original masters and hashes; record transformations and hashes for web/export derivatives. Update the asset manifest and trusted rendering records when integration changes them. Describe generated artwork, reused artwork and code composition accurately.
